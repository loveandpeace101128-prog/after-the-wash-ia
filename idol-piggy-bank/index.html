1 · 概念與計價規則

「愛豆存錢法」是什麼、怎麼算，以及本產品如何把這套玩法變成一個 app。

💡 什麼是愛豆存錢法？

源自日本、在韓國粉圈爆紅的儲蓄遊戲：規定自己「偶像每以某種形式出現一次，就存下一筆對應金額」。發自拍、開直播、上節目⋯⋯每一次心動都變成存錢的觸發器。

  • 情感驅動：不是靠意志力省錢，而是把追星的即時快樂綁定儲蓄行為。
  • 金額自訂：常見設定如發自拍 ₩30,000、限時動態 ₩10,000、留言 ₩5,000，完全依個人財力調整。
  • 變形玩法：對偶像心動就存、搶不到票就存（把失落轉成下次追星的資本）。
  • 知名案例：韓國粉絲想買 ₩769,000 的 AirPods Max，設定「發文 ₩3 萬、限動 ₩1 萬」，原估 3 個月、實際 10 天就存到 ₩455,310。
存下來的錢通常回流到追星本身：演唱會門票、周邊、專輯、遠征旅費——「偶像越努力，我的存錢罐越滿」。

🧮 核心公式

總存款 = Σ ( 事件類型 i 的發生次數 × 該類型單價 )

整個產品的計算核心只有這一條。app 要做的是：

  1. 規則設定：讓用戶為每種「偶像事件」定義單價（幣別可自訂，預設 NT$）。
  2. 快速記錄：事件發生時一鍵 +1（追蹤者常在通勤、上課中滑到貼文，記錄必須 3 秒內完成）。
  3. 自動加總：即時顯示存錢罐總額與目標進度，取代手動表單統計。

單價設計建議（梯度原則）

  • 稀有事件高單價：回歸、演唱會官宣、直播（次數少，單筆存多）。
  • 日常事件低單價：限動、留言（高頻，單價太高會存到破產）。
  • app 會在設定單價時提供「依上月頻率試算每月存款」的預覽，避免用戶設定超出負擔。

🎯 產品定位一句話

「偶像的每一次營業，都自動變成你的存款」——為追星族設計的遊戲化存錢記錄 app，取代手動表單，把統計變成收集的樂趣。

  • 不是記帳軟體：MVP 只做「存入」這一件事；追星支出記錄（演唱會、周邊、小卡）為 V2 衛星功能，以「存 vs 花」對照呈現（見功能 F15 與分頁 3 調研）。
  • 不是銀行服務：MVP 不碰真實金流，是「記錄承諾」的存錢罐（實際轉帳為遠期展望）。
  • 是粉絲的年度回憶錄：512 筆記錄不只是錢，也是「他今年勤勤懇懇營業了 512 次」的證明。

誰在用愛豆存錢法、他們現在怎麼做、哪裡痛。

🎀

24 歲 · 研究生 · 追 K-pop 男團 3 年

28 歲 · 上班族 · 同時追 2 團＋1 位演員

📋 User Stories（MVP 驗收基準）

US-1身為粉絲，我可以建立偶像檔案（名字、應援色、幣別），並為它定義事件類型與單價，這樣我的存錢規則就完全符合我擔的營業型態。
US-2身為通勤中滑到偶像貼文的粉絲，我可以在 3 秒內一鍵 +1 記錄事件，app 自動幫我加上金額與時間，這樣我不會「發的當下忘了記」。
US-3身為為演唱會存錢的粉絲，我可以設定目標金額並隨時看到存錢罐進度，這樣我知道距離見到本人還差多少。
US-4身為統計型粉絲，我可以回顧任意期間的明細與各事件次數統計（像年度總表那樣），並在漏記時補記或修正過去的紀錄。
US-5身為多擔粉絲，我可以切換不同偶像的存錢罐，各自獨立計算，互不干擾。

  1. 晨間通勤：滑 IG 看到限動 ×3 → 開 app 首頁點「IG 限動 +1」三下 → 存錢罐 +NT$30，關掉。全程 5 秒。

🇯🇵 獨立 app		綜合管理支出、追星天數、行事曆、紀念日一站管理
支出功能的調研結論：「純支出記帳」在日本已是紅海、在韓國有 Favvy 卡位，但它們都以「花錢」為中心。我們的機會是以存錢罐為主體、支出為對照：「他營業幫你存了 NT$12,660，你為他花了 NT$34,000」——存與花放在同一面鏡子裡，這個敘事目前沒有人做。

🎯 三視角優化決策（Design Lead × UX Researcher × PM）

視角關鍵風險／洞察已納入規劃的對策
UX Researcher
使用者		最大未驗證假設：「粉絲會在當下記錄」——原始用戶自述「發的當下忘了記」，暗示真實行為可能是批次補記。其次：存錢遊戲可能造成焦慮（營業太多存不起）。原型階段做 5 人訪談＋2 週日記研究；「快速補記」入口與首頁按鈕同等優先；單價負擔試算＋「本月封頂」機制（見 F6）。
Design Lead
設計		Y2K 貼紙風個性最強但最怕「每頁都吵」；金額可讀性是命脈；應援色明度差異大。嚴格視覺 token（貼紙只出現在慶祝時刻與收藏頁、日常記帳克制）；金額永遠置於白底貼紙框、對比 ≥ 4.5:1；應援色經衍生色引擎轉換而非直鋪（見分頁 7 風格 D）。
PM
競爭度		護城河不在功能、在資料：一年 512 筆紀錄＝搬家成本。不跟銀行拚真錢與利息。法務紅線：不得內建偶像肖像素材。年度回顧從 V2 提前為 MVP 後第一優先（Spotify Wrapped 效應）；聚焦記錄的情感價值＋繁中在地化；內建素材僅貼紙/插畫，偶像照片一律用戶自行上傳、僅存本機。

GTM 備註：冷啟動鎖定 Threads／Dcard 追星版——「曬統計圖卡」本身就是內容，產品內建分享即是免費獲客迴路。變現（遠期）：免費 1–2 位偶像，訂閱解鎖多擔＋貼紙包＋拍貼模板；不做廣告。

否決理由（產品負責人拍板＋三視角檢討支持）

  • 定位不符（決定性理由）：三者皆屬「日記型需求」，而本產品的目標是快速記帳＋收集——記錄是 3 秒的反射動作，不是回憶整理工作。
  • UXR 佐證：「保存瞬間」已被相簿／IG 收藏／Weverse 書籤滿足，app 內附件是重複工具；新奇效應會讓試用期數據虛高，投入驗證本身就是成本。
  • PM 佐證：年度回顧不需要依賴附件——拼貼牆直接用事件貼紙（F14 素材）達成，情感厚度由「拍貼顯影＋紀念拍貼」（F16）承擔。
需求的正確歸宿：原始構想「為事件/目標留下視覺記憶」由 F16 目標物顯影 ＋ F14 去背貼紙工房 ＋ F17 貼紙拼貼牆接手——「上傳、裝飾、紀念」集中在目標達成的高光時刻，日常的收集感由自動掉落的貼紙牆承擔。

成立條件（v1.3 補充，佐證：飲料記錄 app 的照片拼貼牆）

照片型記錄只有在「拍照／分享＝記錄動作本身」時才成立：飲料在眼前，拍一張就同時完成記帳與素材收集，照片牆是零額外成本的副產品。偶像事件發生在別的 app 螢幕裡，手動「截圖→切換→匯入」是記帳之外的額外作業，恆不成立。復活條件＝原生 app 的 share extension（IG 分享→自動記帳＋帶圖），屆時「分享」即記錄本身，截圖牆自然成立。

設計鐵律「記錄與裝飾分離」（v1.4 確立）：記錄是 3 秒的反射動作，裝飾是閒暇的儀式感——不同 job、不同時刻、不同心情。任何裝飾性互動（做貼紙、換貼紙、寫字、拼貼）一律放在事後整理時刻（拼貼牆／歷史紀錄／目標頁），永不進入 +1 的當下流程。本原則同時裁決了「每次事件發生時提供做貼紙 option」的提案：貼紙替換放 F17 拼貼牆（長按替換），不放記帳流程。

✂️ MVP 邊界（原型階段刻意不做）

  • 不做帳號系統：原型以裝置本機儲存（localStorage），無註冊登入。
  • 不做自動偵測：不串社群 API 自動抓貼文（各平台 API 限制多），記錄一律手動一鍵完成——「手動但極快」是刻意的產品決策，記錄本身就是儀式感。
  • 不做支出記帳：只記「存入」，不管花費。
  • 不碰真錢：存錢罐是承諾記錄，用戶自行對應到實體撲滿或銀行帳戶。

📐 成功指標（原型驗證用）

  • 記錄一筆事件的操作時間 ≤ 3 秒（從開啟到完成）。
  • 新用戶從開啟到完成規則設定 ≤ 2 分鐘（靠預設模板）。
  • 試算結果與手動表單統計一致（用年度數據 512 筆驗證）。
  • 質化驗證：給 2–3 位實行中的粉絲試用，確認「比表單好用」。

  • 罐子總額 = 該偶像所有 Entry.amount 之和（純推導值，不另存，避免不同步）。
  • Entry.amount 是快照：記錄當下複製 EventType 單價。之後調整單價只影響新紀錄，歷史金額不變——這是規則引擎最重要的一致性決策。
  • 目標進度 = 罐子總額 ÷ targetAmount。多目標時採「共享罐子、逐一達成」：達成第一個後，進度以累計總額對下一個目標門檻計算（原型先支援單一進行中目標，簡化心智模型）。
  • 事件次數統計 = 按 eventTypeId 分組計數 Entry——即分頁 1 試算表的自動化版本。
  • 刪除策略：EventType 不硬刪、只 archived（保護歷史 Entry 的參照）；Idol 刪除需二次確認並連帶刪除其所有資料。

V2 預留實體（本次不實作，schema 先留擴充空間）

  • Expense 支出紀錄（F15）：idolId、category（演唱會/周邊/小卡/專輯/交通/其他）、amount、occurredAt、note、joyScore（幸福度 1–5，借鑑 Joy Money）——與 Entry 平行的第二本帳。
  • Sticker 貼紙（F14）：idolId、imageBlob（去背 PNG，僅存本機）、createdAt——去背貼紙工房的產出，用於目標拍貼頁裝飾。
  • GoalPhotocard 紀念拍貼（F16）：goalId、targetPhotoBlob（目標物照片，設定目標時拍攝，作為顯影素材，僅存本機）、revealStage（顯影階段，由進度推導）、frameTemplate、stickers（引用 Sticker）、achievedStamp（日期＋金額章）。
  • 拼貼牆不需新實體（F17）：月度拼貼牆完全由 Entry（分組計數）＋ EventType 對應貼紙推導渲染，無需額外儲存。

衍生色引擎規格

  • 粉彩底色＝應援色降飽和提亮（HSL: S×0.45、L→88–93%）。
  • 重點色＝應援色原值，僅用於進度條、慶祝動效、小面積貼紙。
  • 固定不變：描邊與文字色恆為深藍紫 #1E1B4B、金額恆置白底貼紙框——跨主題的品牌一致性與可讀性錨點。
  • 對比保險：衍生結果自動檢查對比度 ≥ 4.5:1，不足時自動加深重點色（處理黃色系應援色等高明度情況）。

競品佐證：韓國 Favvy 的「祭壇首頁＋象徵色換膚」驗證了此方向的粉絲接受度（見分頁 3）。
